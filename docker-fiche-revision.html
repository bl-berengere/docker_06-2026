Notions clés · Définitions · Commandes essentielles — CDA

1. Concepts fondamentaux

Docker — Plateforme de conteneurisation : empaqueter une application et toutes ses dépendances dans une unité isolée et portable.
Conteneur (container) — Instance exécutable et isolée d'une image. Léger, démarre en quelques secondes, partage le noyau de l'hôte.
Image — Modèle en lecture seule (read-only) servant à créer des conteneurs. Composée de couches (layers) empilées.
Dockerfile — Fichier texte de recette décrivant comment construire une image, instruction par instruction.
Layer (couche) — Chaque instruction d'un Dockerfile crée une couche. Mises en cache pour accélérer les builds.
Registry / Docker Hub — Dépôt distant stockant les images (ex. hub.docker.com). On y push et pull les images.
Volume — Stockage persistant géré par Docker, indépendant du cycle de vie du conteneur (données qui survivent).
Bind mount — Montage d'un dossier de l'hôte dans le conteneur (ex. votre code source en dev).
Network — Réseau virtuel permettant aux conteneurs de communiquer entre eux par leur nom.
Docker Compose — Outil pour définir et lancer une appli multi-conteneurs via un fichier YAML.
Conteneur vs VM : une VM virtualise tout un OS (lourd, lent). Un conteneur partage le noyau de l'hôte et n'isole que l'application (léger, rapide, quelques Mo).

3. Gestion des conteneurs

CommandeDescription
docker run <image>Créer + démarrer un conteneur depuis une image
docker run -dDetached : en arrière-plan
docker run -p 8080:80Publier un port (hôte:conteneur)
docker run -it <img> bashMode interactif + terminal (ouvrir un shell)
docker run --name webNommer le conteneur
docker psLister les conteneurs actifs
docker ps -aLister tous les conteneurs (même arrêtés)
docker stop / start / restart <c>Arrêter / démarrer / redémarrer
docker rm <conteneur>Supprimer un conteneur arrêté
docker logs -f <conteneur>Afficher les logs (-f = en continu)
docker exec -it <c> bashOuvrir un shell dans un conteneur déjà lancé
docker inspect <c>Détails complets (JSON) du conteneur
docker statsConsommation CPU / RAM en temps réel
run vs exec : run crée un nouveau conteneur à partir d'une image. exec exécute une commande dans un conteneur qui tourne déjà.

4. Docker Compose

CommandeDescription
docker compose upConstruire + démarrer tous les services
docker compose up -dDémarrer en arrière-plan
docker compose up --buildForcer la reconstruction des images
docker compose downArrêter + supprimer conteneurs et réseaux
docker compose down -v... + supprimer aussi les volumes
docker compose psÉtat des services

docker compose exec <svc> bashShell dans un service
docker compose build(Re)construire les images sans démarrer

Structure type d'un docker-compose.yaml

services: app: build: ./docker/php # build depuis un Dockerfile image: php:8.4-fpm-alpine # OU image existante ports: - '8080:80' # hôte:conteneur volumes: - './src:/www' # bind mount (code) environment: - APP_ENV=dev depends_on: - db # ordre de démarrage volumes: db_data: # volume nommé (persistant)

5. Dockerfile — instructions clés

InstructionRôle
FROMImage de base (obligatoire, 1re ligne)
WORKDIRDéfinit le dossier de travail
COPY / ADDCopier des fichiers de l'hôte vers l'image
RUNExécuter une commande au moment du build (ex. installer des paquets)
CMDCommande par défaut au démarrage du conteneur (remplaçable)
ENTRYPOINTCommande principale, non remplaçable facilement
EXPOSEDocumente le port utilisé (informatif)
ENVVariable d'environnement
ARGVariable disponible uniquement au build
RUN vs CMD : RUN s'exécute pendant la construction de l'image. CMD/ENTRYPOINT s'exécute au lancement du conteneur.

6. Volumes, réseaux & nettoyage

Volumes & réseaux

docker volume lsLister les volumes
docker volume rm <v>Supprimer un volume
docker network lsLister les réseaux
docker -v hôte:conteneurMonter un volume

Nettoyage (libérer de l'espace)

docker system pruneSupprimer tout l'inutilisé
docker system prune -a... + images non utilisées
docker container pruneConteneurs arrêtés
docker image pruneImages orphelines
Astuce dépannage : si Docker monte un dossier à la place d'un fichier (erreur « not a directory »), c'est souvent qu'un chemin de bind mount n'existe pas → Docker le crée en tant que dossier. Vérifiez bien le chemin dans volumes:.
